# FitGuard — загрузка на GitHub и запуск проверяющими

Этот файл предназначен для владельца проекта и приёмной комиссии. FitGuard — обычное веб-приложение, которое можно скачать из GitHub и запустить на другом компьютере или VPS.

## 1. Что должно попасть в GitHub

Загрузите весь исходный проект из корневой папки FitGuard, включая `client/`, `server/`, `shared/`, `drizzle/`, `public/` (если папка существует), `Dockerfile`, `docker-compose.yml`, `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `tsconfig.json`, `vite.config.ts`, `.env.example`, `README.md`, `DEPLOY.md`, `GITHUB_SETUP.md` и остальные конфигурационные файлы проекта.

Не загружайте в GitHub:

- `.env` с реальными паролями и API-ключами;
- `node_modules/`;
- `dist/`;
- папки временных логов `.manus-logs/`;
- личные резервные копии базы данных;
- временные скриншоты, если они не нужны для презентации.

В репозитории должен находиться `.env.example`, но не настоящий `.env`. Это позволяет комиссии понять, какие настройки нужны, не раскрывая секреты.

## 2. Создание аккаунта GitHub

1. Откройте [https://github.com](https://github.com).
2. Нажмите **Sign up**.
3. Введите email, придумайте пароль и имя пользователя.
4. Подтвердите email по письму от GitHub.
5. При необходимости пройдите проверку безопасности.
6. После входа нажмите значок **+** в правом верхнем углу и выберите **New repository**.
7. В поле **Repository name** укажите `fitguard`.
8. В описании можно написать: `Information and analytics system for monitoring training progress`.
9. Для проверки комиссией можно выбрать **Public**. Если репозиторий должен быть закрытым, выберите **Private** и добавьте проверяющего через **Settings → Collaborators**.
10. Не ставьте галочку **Add a README file**, потому что README уже есть в проекте.
11. Нажмите **Create repository**.

## 3. Загрузка проекта через GitHub Desktop — самый простой вариант

1. Установите [GitHub Desktop](https://desktop.github.com/).
2. Откройте приложение и войдите через свой GitHub-аккаунт.
3. Выберите **File → Add local repository**.
4. Укажите корневую папку проекта FitGuard, например `/path/to/fitguard` или папку, которую вы скачали на свой компьютер.
5. Если GitHub Desktop сообщает, что папка ещё не является репозиторием, выберите **create a repository** или предварительно выполните команды из следующего раздела.
6. В поле **Summary** напишите `Initial FitGuard application`.
7. Нажмите **Commit to main**.
8. Нажмите **Publish repository**.
9. Проверьте имя `fitguard`, владельца репозитория и видимость Public/Private.
10. Нажмите **Publish repository** ещё раз.

После этого откройте страницу репозитория в браузере и проверьте, что видны `README.md`, `package.json`, `client`, `server`, `drizzle` и `Dockerfile`.

## 4. Загрузка через командную строку

Этот способ подходит для macOS, Linux и Windows Terminal. Откройте терминал в корне проекта:

```bash
cd /путь/к/fitguard
```

Если папка ещё не является Git-репозиторием:

```bash
git init
git branch -M main
git add .
git commit -m "Initial FitGuard application"
```

Подключите созданный репозиторий GitHub:

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/fitguard.git
```

Отправьте код:

```bash
git push -u origin main
```

GitHub может попросить авторизацию. Пароль GitHub в качестве пароля Git больше не используется. В окне авторизации выберите вход через браузер или создайте Personal Access Token с разрешением `repo`.

Если remote уже существует, проверьте его:

```bash
git remote -v
```

Если нужно заменить адрес:

```bash
git remote set-url origin https://github.com/ВАШ_ЛОГИН/fitguard.git
```

## 5. Что написать проверяющей комиссии

В описании репозитория укажите:

> FitGuard — веб-приложение для мониторинга силовых показателей и самочувствия учеников. Ученик заполняет журнал тренировки, система автоматически формирует аналитический отчёт, а тренер видит динамику, графики и индикаторы риска в личном кабинете.

В README уже описаны стек, тестовые аккаунты и запуск. Перед передачей ссылки убедитесь, что репозиторий содержит последнюю версию и не содержит `.env` с секретами.

## 6. Запуск на компьютере проверяющего без Docker

Требования:

- Node.js 22 или новее;
- pnpm 10;
- MySQL или MariaDB.

Проверяющий выполняет:

```bash
git clone https://github.com/ВАШ_ЛОГИН/fitguard.git
cd fitguard
corepack enable
corepack prepare pnpm@10.18.0 --activate
pnpm install --frozen-lockfile
cp .env.example .env
```

После этого в `.env` нужно указать работающую базу данных. Например:

```env
DATABASE_URL=mysql://fitguard:пароль@127.0.0.1:3306/fitguard
JWT_SECRET=локальный-секрет-минимум-32-символа
AI_PROVIDER=
AI_MODEL=
AI_API_KEY=
```

Дальше выполняются миграции и запуск:

```bash
pnpm db:migrate
pnpm seed
pnpm dev
```

Приложение откроется по адресу [http://localhost:3000](http://localhost:3000).

ИИ API-ключ для первого запуска не нужен: базовый детерминированный анализ работает без него. Для расширенного текстового анализа можно позже добавить ключ Groq в `.env`.

## 7. Запуск через Docker Compose

Если на компьютере установлен Docker Desktop, запуск проще:

```bash
git clone https://github.com/ВАШ_ЛОГИН/fitguard.git
cd fitguard
cp .env.example .env
nano .env

docker compose up -d --build
docker compose exec app npx drizzle-kit migrate
docker compose exec app pnpm seed
```

После этого приложение доступно на [http://localhost:3000](http://localhost:3000). Остановить его можно командой:

```bash
docker compose down
```

Полная инструкция для постоянно работающего VPS, домена, HTTPS, Nginx и резервных копий находится в [DEPLOY.md](DEPLOY.md).

## 8. Тестовые аккаунты

После выполнения `pnpm seed` доступны демонстрационные пользователи:

| Роль | Логин | Пароль |
|---|---|---|
| Тренер | `coach` | `coach123` |
| Ученик | `ivan` | `ivan123` |
| Ученица | `maria` | `maria123` |

Для публичного VPS эти пароли нужно заменить или удалить демо-аккаунты.

## 9. На каком языке написан FitGuard

FitGuard состоит из нескольких частей:

- **TypeScript** — основной язык frontend и backend;
- **React** — интерфейс браузера;
- **Vite** — сборка frontend;
- **Tailwind CSS** — стили и адаптивная вёрстка;
- **Node.js + Express** — серверная часть;
- **tRPC** — типизированное соединение браузера с сервером;
- **Drizzle ORM** — работа с базой данных;
- **MySQL/MariaDB** — хранение пользователей, тренировок, связей и отчётов;
- **Recharts** — графики;
- **Docker** — переносимый запуск на VPS.

Браузер загружает React-интерфейс, отправляет API-запросы на Node.js-сервер, сервер проверяет сессию и роль, записывает данные в MariaDB и возвращает результат. Тренер и ученик работают с одной базой, но получают только разрешённые им данные.

## 10. Что происходит с отчётом после отправки тренировки

Сейчас отчёт не отправляется на email и не приходит тренеру отдельным push-уведомлением. После нажатия кнопки приложение:

1. сохраняет тренировку в базу данных;
2. сразу запускает анализ;
3. сохраняет сформированный ИИ-отчёт в базу;
4. показывает отчёт ученику;
5. отображает эту тренировку и риск в дашборде привязанного тренера.

То есть функция передачи данных тренеру **уже работает внутри приложения**: тренер увидит отчёт в своём кабинете. Для этого не нужен VPS — она работает и в локальном запуске, и в Preview, если есть база данных.

Отдельную email-рассылку, уведомления Telegram или push-уведомления нужно будет добавить отдельно. VPS сам по себе не создаёт email-уведомления. Для этого понадобится почтовый SMTP-провайдер или Telegram-бот, отдельные переменные окружения и серверная процедура отправки уведомлений.
